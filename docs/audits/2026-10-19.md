# Release audit · 19 October 2026

The working name is **Ternela**. This audit covers the source-checkout release,
including code, tests, synthetic fixtures, documentation and license notices.
It is a bounded review, not a guarantee that every defect has been found.

## Changes

- One branding file and a tested rename command; imports and stored data stay compatible.
- Removed obsolete research runners and reports from the release. The original research archive remains separate.
- Shared compiler/watch admission, including observable-check coverage, phase consistency, pagination and dependency validation.
- Atomic, flushed blob and manifest writes before database references; checksummed gzip storage.
- Strict JSON, finite numbers, bounded revisions/cursors, and standard JSON Pointer indices.
- Pagination rejects malformed headers and changes of resource or origin. Latest timestamps compare instants across timezones.
- Failed live reads become unknown evidence. The local SDK refuses redirects and non-origin URLs.
- Documentation indexes are reused within a watch engine; wake-up reads have a dedicated SQLite index.
- The interface uses server-selected evidence values, preserves exact integers in its table and receipt downloads, and stops displaying success after evidence expiry.
- CI runs tests, known regression scenarios, Python lint/format checks and JavaScript syntax checks.

## Validation

**108 unit/API tests and 41/41 known simulated scenarios pass.** The scenario
suite reports zero structural issues and zero false ready/complete outcomes.
The tests include concurrent revisions, malformed input, storage races,
identity/type preservation, pagination, expiry and event delivery.

A fresh task went through real model compilation and a real public GitHub read.
The first run exposed a requirement with no executable check; admission rejected
it. Sharing that rule with compiler feedback and clarifying execution constraints
allowed the repeated task to pass admission. **One GET evaluated four metadata
checks and returned complete.** This single smoke test does not establish broad
semantic generalization. Compilation still required bounded retrieval expansion.

The workbench was exercised in a browser: an invalid quantity stopped the dependent
preview; zero remained a valid integer. Desktop and narrow viewport captures were
inspected. The interface detector reported no findings.

Jev was not run: no TypeSafe API credential was configured. It is not represented
as a code-review or correctness guarantee.

## Local timing

Same machine and Python 3.13.3, 30 iterations, synthetic evidence and temporary
storage. Medians in milliseconds:

| Operation | Before | Audited |
|---|---:|---:|
| Create watch after the first index load | 48.279 | 1.836 |
| Submit an observation | 1.533 | 1.526 |
| Read current watch | 0.722 | 0.823 |
| Read a wake-up window | 1.446 | 1.062 |

Cold creation measured 59.595 ms before and 66.247 ms after. Warm creation benefits
from reusing documentation indexes; current-watch reads now include exact formatted
evidence. These are local samples, not throughput, concurrency or service guarantees.
Rerun with `python3 -m ternela.benchmark`.

A separate clean checkout downloaded its public evidence from scratch and passed
all 108 tests, all 41 known scenarios and the deterministic demo. Python 3.11 syntax
also passes; local execution used Python 3.13.3. CI covers Python 3.11 and 3.13.

## Limits

The service remains an alpha for one local host. Authenticated connectors,
verified provider webhooks, automatic provider polling, tenant isolation and
distributed workers are still planned. Passing tests do not prove a model has
captured every condition in an arbitrary task or that a later action is atomic
with its observation. Standalone wheel installation is not validated.
