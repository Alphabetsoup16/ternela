# Local UI refinement — 2026-10-20

The prior view opened on a simulated payment task and put API operations before the
controls needed to check it. Live reads, replay, compilation and product explanation
competed on one page. The refinement preserves the existing palette and native
controls while changing the hierarchy around a single watch.

## Changes

- Live public quick starts appear first; the initial task is GitHub Actions status.
- A small inline form creates GitHub Status or exact PyPI/npm watches and performs
  the first read. Scheduling remains off until explicitly started.
- Status and check controls precede the evidence table. Simulations, activity, plans,
  receipts, reset and compilation remain available through named disclosures.
- Quick-start selection restores its existing watch. Saved URLs recover custom
  watches; missing watch URLs expose a recovery path instead of an empty view.
- A native mobile selector replaces the desktop navigation list. Table overflow
  stays inside its keyboard-focusable region.
- Form metadata, provider/status names and display helpers are centralized in the
  existing application script. Shared styles use one token set, without an added
  frontend runtime, library or build requirement.

## Validation and limits

All **241 existing tests pass** (146 general, 9 safety, 86 workbench). JavaScript syntax,
unique HTML IDs and release-bundle validation pass. The suite verifies the backend;
it is not a browser automation suite or an independent usability study.

Browser checks exercised live GitHub Status, a scoped npm package (`@types/node`
22.10.2), an invalid npm version followed by correction, a fresh PyPI `httpx` 0.27.2
watch, schedule start/pause, watch reuse across navigation, saved custom-watch reload,
a wrong-payment simulation, and lazy receipt inspection. The first PyPI read completed
from the create action. No provider account, model call or external write was used.

Desktop and 390px mobile layouts were inspected together. The mobile page did not
scroll horizontally. Keyboard focus is visible, native form controls retain labels,
status has text as well as color, and reduced motion is supported. Semantic text
color pairs exceed 4.5:1 in a token-level contrast calculation; this is not a complete
assistive-technology certification or coverage of every browser/OS combination.

The mechanical design scan reported two `cramped-padding` warnings on sections with
`padding-block` tokens. Browser-computed top padding was 21px for the checks section
and 14px for disclosures. These are scanner false positives; horizontal padding was
not added to simple section dividers. Compressed suite/scan logs are kept in ignored
`data/audits/ui-refinement-2026-10-20/`.

A pinned formatter was used as development tooling only. [UI maintenance guide](../ui.md)
describes the component boundaries and extension rules. The earlier distribution
review remains evidence of its recorded source snapshot, not the hash inventory of
this later UI change. Native Windows and a published-release trial remain unverified.
