# Native local storage and recovery — 2026-10-20

The Docker demo now uses an owned local volume. Management files and compressed
backups stay in its installation folder. No data was uploaded or published.

## Evidence

- 350 tests pass on macOS and in an isolated directory on the actual Docker state
  volume. The volume run used a read-only, network-disabled, unprivileged helper.
  It exercised executable test fixtures on native storage without changing the
  deployed container's noexec `/tmp` policy.
- 41/41 frozen semantic regression cases pass with zero false ready/complete and
  zero structural issues. macOS also passes 10/10 historical receipt comparisons;
  the isolated volume suite starts with no private receipt corpus.
- Competing processes are excluded by `flock`, `lockf` and SQLite's writer lock
  on the actual volume. An attempted backup while the supervisor runs is rejected.
- Migration compared 310 entries, including 245 regular-file hashes. Database
  integrity, schema version 3/history and every table row matched. The 13 watches,
  4 consumer checkpoints and 12 outbox messages present at migration were preserved.
- A new anonymous GitHub Status observation produced a ready decision. Its named
  consumer received the same unacknowledged message after restart, acknowledged it,
  and resumed without receiving it again. The existing client's session refreshed;
  the probe monitor was paused.
- The host backup command exported compressed state and resumed the app. Restoring
  it into a separately initialized local installation preserved 14 watches, evidence,
  consent and the acknowledged consumer. Corrupt input failed without replacing
  state and the original app restarted. Normal remove/start retained the volume;
  purge removed only that owned disposable installation and its resources.

Transfer tests cover tampered bytes, unsafe paths/links, duplicate members,
truncation, bounded size, hardlinked regular files, an active supervisor,
interrupted replacement, committed cleanup, foreign volume ownership, unmigrated
folders and failed restart reporting. Existing update/rollback tests remain intact.

## Boundaries and recovery

The native volume replaces the Mac folder mount that failed cross-process locks;
that failure evidence remains in the earlier architecture audit. The first copy
comparison paused the move; a fresh comparison and reordered validation succeeded
before startup. The stopped original install and prior image were retained through
verification. Following explicit user authorization, the inactive folder state and
redundant application copy were deleted after checking their retained archives. All
regular files matched; the archived SQLite state passed integrity and logical-data
comparison. This reclaimed 7,671,049 bytes. Compressed rollback snapshots and the
prior image remain available; the live container stayed healthy.

Hashes detect mismatched bytes, not a trusted publisher. Restore only your trusted
backups: they include application code and saved update consent. Recovery tests
cover process interruption and I/O failures, not physical power-loss certification.
Native Windows, every Docker filesystem backend and production load remain unverified.
No new dependency, paid inference, remote storage or release was introduced.

Compressed local evidence and probe reproductions live in ignored
`data/audits/storage-2026-10-20/`. User data and payloads are excluded from this report.
