# First release qualification — 2026-10-20

Candidate: **v0.1.1**, the first public application release. Existing local
v0.1.0 installs have a strictly newer version to receive. Apache-2.0 licensing,
third-party notices and the upstream MIT license texts ship in the application
archive. No dependency was added to the Python runtime.

## Checks

- 355 unit/API tests pass on macOS ARM64 / Python 3.15 and Linux ARM64 /
  Python 3.15 and 3.11.17. The local Mac check also compares 10 historical receipt
  examples; private receipts are excluded from the release and isolated tests.
- 41/41 known simulated regressions pass, with zero false ready/complete outcomes
  or structural issues in that set. All 55 frozen GitHub Status cases pass.
- Ruff 0.17.1 lint and format checks pass. Seed setup and the deterministic replay
  run offline from the extracted application archive.
- A fresh managed container install preserves update opt-out, watch decisions,
  unacknowledged delivery across restart, and acknowledged consumer progress. Real
  compressed backup/restore recovers the saved state; invalid input leaves it
  intact. Normal removal/start preserves data; the disposable install is purged
  afterward using its ownership-checked launcher.
- The Docker recovery probe exercises successful automatic updates, startup
  failure with candidate data changes, restoration of the previous data, interrupted
  recovery, failed bundled-image fallback and an uncertain commit boundary.
- A disposable container using the deployed **v0.1.0 immutable launcher** accepts
  the v0.1.1 archive, retains its watch/consumer acknowledgement and keeps a backup.
  The local tests use real archive bytes and synthetic remote metadata/transport.
- Bundle checks cover manifest hashes, repeated-build equality, extraction, license
  inclusion, upload/download equality and absence of local state, credentials,
  Git metadata or private receipt corpora. Release asset verification is recorded
  separately after draft upload so the archive does not contain its own digest.

## Findings repaired

1. The upgrade probe passed a macOS `/var` temporary alias to Colima, where only
   its resolved `/private/var` location was shared. Resolve the fixture path before
   constructing the mount. The original failure log is retained privately.
2. Python 3.11 rejects `compresslevel` on a streaming `tarfile.open`. Wrap its tar
   stream in `gzip.GzipFile` instead. Existing archive round-trip, tamper, link,
   truncation and interruption tests pass on both Python versions.
3. Top-level upstream license files were absent from the application allowlist.
   Move their canonical copies into `docs/licenses` and correct the notice links.
   This preserves compatibility with the installed immutable verifier.

One initial Linux harness used Docker's non-executable temporary mount; the mock
Docker scripts could not run. The isolated test harness now explicitly enables
execution for temporary fixtures. Product container settings are unchanged.

## Limits and publication

This is a single-host alpha. Native Windows installation has not been validated;
PowerShell remains experimental. Upgrade tests cannot establish the real public
GitHub update hop while the release is a draft. Publish only after verifying the
draft assets and tag, then check that final hop from a disposable opted-in v0.1.0
installation. Do not infer production reliability from finite, implementation-authored
fixtures or a successful startup check.

The existing GitHub workflow covers Python 3.11 and 3.15. Its exact release-commit
result is checked remotely before publication. The local live registry/status
smokes retain full receipts in ignored audit storage; those are observations, not
provider reliability guarantees. Compressed operator logs and initial failures
remain private.

## Publication verification

v0.1.1 is published with **macOS as the sole supported host**. The release tag
remains on the tested application commit; current main adds support-policy prose.
GitHub's asset digests/sizes and downloaded bytes match the frozen candidate.

A disposable opted-in v0.1.0 installation used the real public GitHub endpoint,
asset download, byte verification and automatic apply path to reach v0.1.1. Its
watch, named-consumer acknowledgement, preference and pre-update backup survived.
Opt-out blocked automatic work before consent; a second public check found no
newer version, and the old client refreshed its session after the app restarted.
The live user installation was unchanged; disposable resources were removed.
