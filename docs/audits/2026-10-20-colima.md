# Colima migration — 2026-10-20

Ternela now runs in Colima's Docker engine at the same loopback URL. The user's
follow-up scoped this cutover to Ternela; other agents' workloads and the global
`desktop-linux` context remain on Docker Desktop. Desktop stays installed with
Ternela's source volume/image/container retained for rollback.

## Preserved state

The source app was stopped before export. The destination matched 318 file/link/
directory entries, including 250 regular-file hashes, and every SQLite table row.
This preserved schema 3/history, 14 watches, 5 consumer checkpoints and 14 outbox
messages present at cutover. Saved automatic-update consent remained false. All
49 deployed canonical Python files match the current source after a verified
application refresh. A compressed full-state backup remains in the install folder.

## Validation

- 355 tests pass on macOS and in an isolated directory on Colima's actual native
  state volume. The Colima helper ran unprivileged, network-disabled and with a
  read-only image filesystem; tests used native temporary storage.
- 41/41 frozen semantic regression cases pass with zero false ready/complete or
  structural issues. macOS also passes 10 historical receipt comparisons. The
  isolated Colima run contains no private historical receipt corpus.
- Competing-process `flock`, `lockf` and SQLite writer exclusion pass on that volume.
  A backup request while the supervisor owns state fails as expected.
- A fresh anonymous GitHub Status read produced a ready receipt. Unacknowledged
  delivery survived a container restart; acknowledgement and automatic local-session
  refresh worked. The probe monitor was paused afterwards.
- A managed Colima backup restored into a separate local installation with all
  15 current watches, 6 consumers, consent and acknowledgement intact. Invalid
  input preserved the original state and resumed the app. Normal remove/start
  retained the probe data; purge removed only the owned disposable probe.
- A shared VM resize/restart occurred during checks. The engine identity and volume
  survived and Ternela returned healthy; this was observed rather than initiated
  as a resource benchmark.

The test run exposed a SQLite startup race when concurrent initializers enabled
WAL mode. Startup now checks the current mode and retries only BUSY/LOCKED failures
with a bounded wait, closing the competing connection before retry. Nonlocking
errors still propagate, and future database formats are rejected before changing
journal mode. Deterministic transient/permanent/deadline tests and 40 repeated
four-initializer trials pass on both macOS and Colima. The original failure evidence is retained.

Both launchers record a context on new installs and honor an existing
`.ternela-context` for every engine operation, including binary transfers.
Explicit selection beats unrelated shell/global context settings. Legacy installs
without the marker retain their current-context behavior and engine check. Tests
exercise the saved context, hostile inherited endpoint settings and a symlinked
context marker. Native PowerShell/Windows execution remains unverified.

The Colima skill is installed in `~/.codex/skills/colima` for other agents. It covers
explicit contexts, project ownership, native volumes, consistent backups, shared
VM lifecycle, macOS mounts and credential/plugin independence from Docker Desktop.
The skill passes the bundled validator. Standalone Homebrew CLI/Compose/Buildx
and macOS Keychain helper are installed; registry credentials were copied without
printing their values, with originals retained.

## Scope and evidence

No other project was stopped, started, migrated or deleted by this Ternela cutover.
The initial broader inventory was retained privately to help the user's later
cutovers. Colima and Desktop are both still running, so this work does not claim
measured host RAM savings. The other workloads must finish moving before Desktop
can be safely retired. No cloud storage, dependency in the Ternela runtime, CI or
public release was introduced.

Compressed private migration data and reproductions live in the task's
`results/colima-migration/`; public documentation contains aggregate results only.
