# Ternela v0.1.2

See an agent stop, receive an event, and resume from one button in the workbench.
This release adds the real local export handoff demo, its five-stage timeline,
and an illustrated walkthrough. It remains an Apache-2.0 local alpha.

## Try it

Existing installs: run `sh ~/ternela/ternela.sh update` using your install folder,
open its workbench URL, and click **Run agent demo**. Automatic-update preferences
are preserved. No host Python, provider account or model login is required.

For a new install on macOS, start Colima or Docker Desktop. Download
`ternela-v0.1.2.tar.gz` and `SHA256SUMS` from the release assets, then:

```sh
shasum -a 256 -c SHA256SUMS
mkdir ternela-v0.1.2
tar -xzf ternela-v0.1.2.tar.gz -C ternela-v0.1.2
cd ternela-v0.1.2
sh scripts/ternela.sh install
```

Use the uploaded application archive; GitHub's generated source archives omit the
verified API source seeds. The first local image build needs network access.

## What the demo proves

A reference agent creates a watch and exits. A separate process writes a real CSV.
Ternela verifies its completion evidence and saves a durable delivery; the runner
launches the continuation, checks its summary, and acknowledges the event.
The UI displays actual event times, including a five-second stopped interval, and
lets you inspect the CSV and verified answer. Reloading recovers the saved run;
repeated clicks reuse an active attempt. Logs are compressed and finished runs
have bounded retention.

The UI uses a deterministic reference agent and makes no model calls. The optional
CLI adapter can resume the exact recorded Codex session using an existing login.
It was exercised with two real model turns during feature development. Neither
mode establishes independent truth of arbitrary producer reports or exactly-once
external actions. See [the demo guide](../agent-demo.md).

## Validation and compatibility

385 unit/API tests and 41/41 existing simulated regression scenarios pass. Desktop
and mobile UI runs, real child processes, recovery/failure paths, token/origin
checks and the protected UI API were exercised. Release preparation validates the
exact extracted application bundle and upgrade recovery before publication.

Supported host remains macOS. Linux is the container runtime; Windows and Linux
hosts are unsupported. Stored schema/plan/receipt formats are unchanged. Updates
preserve saved watches, consumer cursors, evidence and update consent, and do not
replace the immutable launcher, host scripts or Python image.
