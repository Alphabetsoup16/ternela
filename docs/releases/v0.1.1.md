# Ternela v0.1.1

First public application release. Ternela is an Apache-2.0 alpha for agents that
need a persistent wait, fresh evidence and a recoverable decision queue.

## Try it

Download `ternela-v0.1.1.tar.gz` and `SHA256SUMS` from this release. Verify the
archive before extracting it into a new folder:

```sh
shasum -a 256 -c SHA256SUMS
mkdir ternela-v0.1.1
tar -xzf ternela-v0.1.1.tar.gz -C ternela-v0.1.1
cd ternela-v0.1.1
sh scripts/ternela.sh install
```

**Supported host: macOS.** Start Docker Desktop or Colima first.
The installer builds locally; the first build needs network access. It asks
whether to enable automatic stable-release updates; the default is no. No
provider account or host Python is required for public checks and bundled replays.
Use the uploaded application archive, which includes pinned source seeds.
GitHub's automatically generated source archives do not include those seeds.

## Included

- A local workbench for inspecting watches, evidence and decisions.
- Account-free GitHub, GitHub Status, PyPI and npm reads.
- Persisted automatic checks, evidence expiry and bounded retry/backoff.
- Durable decision delivery with named consumers and acknowledgement.
- A local container installer, compressed backups and restore, opt-in application
  updates, startup rollback and interrupted-upgrade recovery.
- Shared connector contracts and failure fixtures; missing evidence remains unknown.

## Compatibility and limits

This is a single-host alpha, not a hosted or multi-tenant service. The container
uses Linux and Python 3.15; Python source requires 3.11 or newer. Windows and
Linux hosts are unsupported for this first release. Bundled instructions for those
hosts are development reference, not a support commitment.
Authenticated connectors, verified webhooks and distributed workers are planned.
Arbitrary task compilation requires a signed-in Codex CLI outside the image.

Existing local v0.1.0 installs can receive the application bundle through their
manual update command or previously enabled automatic updates. Application updates
do not replace the immutable launcher, Python image or host management scripts.
Older folder-backed installs require the documented storage migration before using
the native-volume management scripts. Back up valuable data before updating.

SHA-256 checks detect changed bytes; trust still depends on the chosen repository
and publisher. Rollback checks startup health, not every possible later behavior.
A receipt records bounded evidence and can expire before an agent acts.

## Validation

The release candidate is checked as an extracted application bundle, including
unit/API tests, the frozen simulated regression corpus, fresh container install,
upgrade/rollback recovery and persistent state. Exact results and environment
limits are recorded in the [release audit](../audits/2026-10-20-release.md).
The public GitHub update hop can only be tested after publication; local transport
fixtures do not establish that final hop.
